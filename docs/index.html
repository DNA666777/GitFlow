Le Gitflow standard, sans quitter Visual Studio

Démarrez et terminez vos branches feature/ release/ hotfix/ , en respectant strictement le Gitflow Workflow d'Atlassian. Merge local par défaut, ou Pull Request sur GitHub et Azure DevOps quand vos branches sont protégées.

Démarrage rapide Lire le guide complet
⚡

Menu et fenêtre

Démarrer, pousser et terminer depuis le menu Extensions > GitFlow ou la fenêtre GitFlow.

🛡️

Sécurité

Refus s'il y a des modifications non commitées, arrêt sur conflit avec reprise, jamais de push --force, reset --hard ni de branche non mergée supprimée.

🔀

Pull Requests (option)

Branches protégées ? Terminez par PR sur GitHub ou Azure DevOps : message généré, suivi, tag créé après le merge.

📝

Commit

Liste des modifications et message de commit généré depuis git (fichiers, lignes, tickets), modifiable.

🧩

Dépendances

Seulement Visual Studio et Git for Windows. Pas de git-flow, pas de gh ni d'az : vos identifiants git suffisent.

📜

Journal

Chaque commande git exécutée apparaît dans Sortie > GitFlow, avec son code retour.

Démarrage rapide

Prérequis

  • Visual Studio 2022 17.14+ ou Visual Studio 2026.
  • Git for Windows (installé avec Visual Studio) : la commande git doit être dans le PATH.
  • Une solution ouverte dans un dépôt Git qui contient au moins un commit.

Premiers pas

  1. Installez l'extension : fermez Visual Studio, double-cliquez sur GitFlow.VSExtension.vsix, validez, relancez Visual Studio. Détails
  2. Ouvrez la fenêtre GitFlow : Extensions > GitFlow > Fenêtre GitFlow. Elle s'ouvre en onglet à côté de Git Changes.
  3. Initialisez le dépôt : bouton Initialiser GitFlow…, vérifiez les noms proposés (master, develop, feature/…), OK. La branche develop est créée.
  4. Démarrez une feature : type Feature, nom login, Démarrer. Vous êtes sur feature/login.
  5. Travaillez et commitez depuis la section Commit de la fenêtre : le message est proposé, modifiez-le si besoin, Commiter.
  6. Terminez : Terminer… sur la ligne de la branche. Merge --no-ff dans develop, branche supprimée, retour sur develop.
Pour aller plus loin

Le guide complet couvre les releases, les hotfixes, les conflits et les paramètres. Si master et develop sont protégées sur votre serveur, lisez le mode Pull Request.
