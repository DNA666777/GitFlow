Reference and troubleshooting

The rules applied, the configuration keys and answers to common problems.

The model in short

The extension strictly follows the Atlassian Gitflow Workflow, with no variant. One difference: the production branch is called master by default (configurable).

TypePrefixStarts fromFinishes intoTagSuggested version
Featurefeature/developdevelopno—
Releaserelease/developmaster then developyesminor + 1 (1.4.1 → 1.5.0)
Hotfixhotfix/mastermaster then develop (or the release in progress)yespatch + 1 (1.5.0 → 1.5.1)
  • No other branch type (no bugfix/, support/…).
  • Merges with --no-ff, no squash or rebase. Annotated tags {prefix}{version}, message Release x.y.z / Hotfix x.y.z, editable.
  • Only one release and one hotfix in progress at a time.

Safety rules

Uncommitted changesStart and Finish refused. The extension never stashes automatically: commit or run git stash yourself. Untracked files don't block.
Checks before actingBase branch exists, name valid for git (git check-ref-format), target branch doesn't exist, tag doesn't exist.
Merge conflictImmediate stop, nothing deleted, can resume after resolution.
Forbidden commandsNever push --force, reset --hard, branch -D. An unmerged branch is never deleted.
CommitsRefused on the production branch and during a merge.
Pull RequestsCreated and tracked, never approved or merged by the extension. The tag is only created on a merge commit verified on origin/master.
CredentialsAsked from git each time, never stored or written to the logs.

Configuration keys

Stored in the repository git config (--local) or the user git config (--global, defaults for new repositories). The local value wins.

Tracked PRs are stored in the local config under gitflowvs-pr.<branch>.link, and removed when the branch is completed.

Git commands run

All commands go through the git of Git for Windows: your hooks, GPG signatures, LFS and credentials apply just like in a terminal. They are visible in View > Output, GitFlow channel:

=== GitFlow: finishing feature/login ===
[10:42:03] git switch develop  → 0 (81 ms)
[10:42:03] git merge --no-ff -m "Merge branch 'feature/login' into develop" feature/login  → 0 (153 ms)
[10:42:03] git branch -d feature/login  → 0 (54 ms)
OK

Troubleshooting

The GitFlow menu doesn't appear

Check Extensions > Manage Extensions > Installed. If the extension is not there, reinstall the .vsix with Visual Studio closed: if it is open, the Visual Studio Installer closes without installing anything.

A click does nothing

Look at the GitFlow channel of the Output window, then at the extension log: %TEMP%\servicehub\logs\*GitFlow.VSExtension*.log.

"No Git repository found"

The extension looks for the repository from the open solution, then the selected item, then the active document. Open a solution located in a Git repository.

"Some changes are not committed"

Commit (Commit section) or run git stash, then try again. Untracked files don't count.

My changed files don't appear in Commit

Save them (Ctrl+S): git only sees files written to disk.

The suggested release version already has a tag

The next version is computed from the highest version tag on master. Type another version: an existing tag is refused.

"Pull Request mode unavailable"

The origin remote is neither GitHub nor Azure DevOps (a local folder, GitLab, Bitbucket…): use local merge. Check the URL with git remote -v. For a company Azure DevOps server, check the matching option in the settings (details).

"The platform rejected the request"

The message from GitHub or Azure DevOps is shown as is: insufficient rights, PR already exists, missing target branch… After fixing it, run Finish… again: an already open PR is reused.

"The branch has no commit in common with origin/master"

The repository was created on the server with a first commit (often a README), and the local history was pushed beside it: the two master branches share no ancestor, and a pull request could not be merged. Nothing is pushed. Join the two histories once, then run Finish… again:

git switch master
git merge origin/master --allow-unrelated-histories
git push

The merge often stops on a README conflict: keep the version you want, git add, then git commit.

Complete refuses: branch not contained in develop

The PR was merged with squash or rebase: the branch commits are not in develop. Nothing is deleted. If the content was delivered, delete the branch yourself: git branch -D feature/x.
