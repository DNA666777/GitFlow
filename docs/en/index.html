The standard Gitflow, without leaving Visual Studio

Start and finish your feature/ release/ hotfix/ branches, strictly following the Atlassian Gitflow Workflow. Local merge by default, or Pull Requests on GitHub and Azure DevOps when your branches are protected.

Quick start Read the user guide
⚡

Menu and window

Start, push and finish from the Extensions > GitFlow menu or the GitFlow window.

🛡️

Safety

Refuses to run with uncommitted changes, stops on conflicts and can resume, never runs push --force or reset --hard, never deletes an unmerged branch.

🔀

Pull Requests (option)

Protected branches? Finish through a PR on GitHub or Azure DevOps: generated message, tracking, tag created after the merge.

📝

Commit

List of changes and a commit message generated from git (files, lines, tickets), editable.

🧩

Dependencies

Only Visual Studio and Git for Windows. No git-flow, no gh, no az: your git credentials are enough.

📜

Log

Every git command appears in Output > GitFlow, with its exit code.

Quick start

Requirements

  • Visual Studio 2022 17.14+ or Visual Studio 2026.
  • Git for Windows (installed with Visual Studio): the git command must be on the PATH.
  • A solution opened in a Git repository that has at least one commit.

First steps

  1. Install the extension: close Visual Studio, double-click GitFlow.VSExtension.vsix, confirm, restart Visual Studio. Details
  2. Open the GitFlow window: Extensions > GitFlow > GitFlow Window. It opens as a tab next to Git Changes.
  3. Initialize the repository: Initialize GitFlow…, check the suggested names (master, develop, feature/…), OK. The develop branch is created.
  4. Start a feature: type Feature, name login, Start. You are now on feature/login.
  5. Work and commit from the Commit section of the window: a message is suggested, edit it if needed, Commit.
  6. Finish: Finish… on the branch row. --no-ff merge into develop, branch deleted, back on develop.
Going further

The user guide covers releases, hotfixes, conflicts and settings. If master and develop are protected on your server, read Pull Request mode. Using VS Code? See GitFlow for VS Code.
